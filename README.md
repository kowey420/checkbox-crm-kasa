# Каса для Checkbox

Облікова система (CRM) для роботи з [API Checkbox](https://wiki.checkbox.ua/uk/api):
веб-інтерфейс у браузері, локальна база товарів, продаж, зміни, платіжний термінал, журнал чеків.

> Незалежний проєкт, не є офіційним продуктом Checkbox.

## Можливості

### Продаж
- **Оплата** готівкою (із заокругленням до 50 або 10 коп.), карткою через термінал і «Іншою» оплатою:
  безготівкова чи готівкова, з назвою в чеку зі списку (Сертифікат, Бонуси, Переказ на рахунок,
  Інтернет Банкінг, Інтернет Еквайринг) або своєю — список можна доповнювати й чистити
- **Плитки**: групи — папками, товари — картками зі значком (штучний / ваговий / акцизний), підгрупи всередині,
  «хлібні крихти» й «Назад», кількість у кошику на плитці; перемикач «Плитки / Список» (дерево груп)
- **Власні зображення плиток**: ПКМ по товару чи групі → «Встановити зображення…» або перетягнути файл на плитку
  (зменшується до 256 px, зберігається лише локально, у папці `images`)
- **Сканування підряд** (кнопка «▦ Сканувати підряд» або F2): скан за сканом зі звуком, вага й акцизні марки
  прямо у вікні, «Прибрати останнє», далі одразу «Готівка» чи «Картка»
- **Знижки й надбавки** на товар і на весь чек — відсотком або сумою (у чек ідуть сумою)
- **Телефон покупця**: копія чека в SMS/Viber (`delivery.phone`) — у продажі, передплаті, доплаті й поверненні
- **Акцизні марки**: рівно 10 символів, кнопка «+» або Enter; продану марку каса не дасть продати вдруге
  (ні при скануванні, ні на сервері), поки її не повернуть чеком повернення чи поверненням замовлення.
  Марки з чеків інших кас — після «Завантажити з Checkbox» у журналі

### Повернення, передплата
- **Повернення** з журналу за чеком продажу: вибір товарів і кількості, частинами, з урахуванням знижок;
  готівкою або на картку — через термінал (POSSrv «Відміна / повернення» з RRN продажу та id пристрою) чи вручну
- **Передплата й післяплата**: чек передплати з усіма товарами й внеском, доплати частинами, післяплата,
  що закриває замовлення, повернення всього замовлення; вкладка «Передплати» зі станом кожного замовлення

### Зміна й звіти
- Відкриття (зокрема прямо з вікна оплати), закриття з Z-звітом у PNG з пропозицією винести готівку, X-звіт у PNG,
  залишок готівки, службове внесення й винесення
- **Автоматичне закриття зміни**: у налаштуваннях — прапорець «Закривати зміну автоматично» і час у 24-годинному форматі (не пізніше 23:45); при відкритті зміни каса передає Checkbox
  `auto_close_at` (найближчий такий момент, UTC), і Checkbox закриває зміну сам
- **Податкові ставки й зміна**: зміни ставок у кабінеті Checkbox діють лише з наступного відкриття зміни, тому каса
  оновлює довідник ставок перед кожним відкриттям; якщо ставки змінились посеред зміни — попередження на вкладках
  «Зміна» й «Податкові ставки», а товар зі ставкою, що в цій зміні ще не діє, каса пробити не дасть
- **Журнал чеків** за 7 днів по днях і змінах (з Checkbox): продажі, повернення, внесення, винесення; PNG чека з друком
- **Z-звіти** зберігаються в касі назавжди: закриті з цієї каси — одразу, з Checkbox — за останні 7 днів
  кнопкою «Завантажити з Checkbox» (`GET /reports`, `is_z_report=true`; запасний — `/reports/search`);
  таблиця з продажами, поверненнями, кількістю чеків і готівкою, посилання «Z-звіт» біля зміни в журналі;
  зображення звітів кешуються на диску (`reports/`)

### Товари (вкладка з меню зліва)
- **Товари**: плитки або таблиця, пошук, додавання й редагування. Код нового товару заповнюється сам —
  наступний вільний (↻ — згенерувати знову). Зміни одразу діють у касі, а в Checkbox ідуть пакетом:
  змінені — `PUT /goods/{id}` (поточний стан товару + правки), нові — `POST /goods` (або імпортом);
  помилка одного товару не зупиняє решту. «Залишковий товар» і залишок — поставкою через імпорт
  з автопоставкою (лише збільшення) зі звіркою після неї
- **Групи товарів**: дерево груп і підгруп з редагуванням одразу в Checkbox — створити, перейменувати,
  перенести, видалити, перенести товари
- **Податкові ставки**: довідник організації; оновлюється кнопкою «⟳ Оновити ставки»
- **Акцизні марки**: перелік проданих і повернутих марок із пошуком
- **CSV**: експорт товарів для сайту, імпорт/перевірка, вивантаження й завантаження номенклатури Checkbox

### Інше
- **Платіжний термінал** через POSSrv (ПриватБанк PAX A930, Ощадбанк Ingenico): оплата й дані ЕПЗ у чек автоматично
- **Шапка**: стан зміни, фіскальний номер каси (з назвою й адресою в підказці), ім'я касира
- **Темна тема**: перемикач у шапці (авто / світла / темна)
- **Значок у треї Windows**: відкрити касу, папку з логами, поточний лог, вийти
- Автоматичний вибір вільного порту, оновлення з GitHub

## Навантаження на Checkbox
Каса намагається не робити зайвих запитів:
- **Авторизація** — токен касира зберігається в `token.json`; `POST /cashier/signin` лише якщо токена немає,
  він застарів (401) або змінились облікові дані
- **Стан зміни** кешується на 10 хв; свіжий запит — на вкладці «Зміна», перед закриттям зміни
  та для службового винесення; відкриття/закриття з каси оновлюють кеш одразу
- **Товари** звіряються з порталом раз на день — перед першим відкриттям зміни; закриття й наступні
  відкриття лише відправляють локальні правки. Повна синхронізація — кнопкою «⟳ Синхронізувати».
  Товари — сторінками по 1000 (якщо Checkbox не прийме — по 100)
- **Групи** при автоматичній синхронізації — лише коли в товарах з'явилась невідома група
- **Податкові ставки** — перед відкриттям зміни (саме тоді діють зміни з кабінету), коли довідник порожній або кнопкою
- **Дані каси** (фіскальний номер) — раз на ключ ліцензії
- **Статус чека й зміни** — перший запит через 0,3 с, далі кожні 0,5 с (у межах 2 запитів на секунду)
- **429 «Занадто часто»** — каса сама чекає, скільки просить Checkbox, і повторює

## Встановлення

### Windows — готова програма
Завантажте `Kasa.exe` з [останнього випуску](../../releases/latest) і запустіть. Python не потрібен.

### Mac
Завантажте `Kasa-mac.zip` з [останнього випуску](../../releases/latest), розпакуйте й перетягніть «Каса»
в «Програми» у Finder. Інструкція для першого запуску — у «Прочитай мене.txt» в архіві.

macOS запускає завантажені програми з тимчасової копії «лише для читання» (App Translocation), поки на них
є позначка «з інтернету». Каса сама знаходить свою справжню папку, оновлюється туди й знімає цю позначку.
Якщо стара версія каси не може оновитися, виконайте один раз у Терміналі:
`xattr -dr com.apple.quarantine /Applications/Каса.app`

### Будь-яка система — через Python 3.9+
Завантажте `kasa-py.zip` (або склонуйте репозиторій) і запустіть:
- Windows — `Запустити касу.bat`
- macOS / Linux — `Запустити касу.command` або `python3 checkbox_web.py`

Сторонні бібліотеки не потрібні; для значка в треї Windows — `pystray` і `Pillow`
(`Запустити касу.bat` встановить їх сам).

## Налаштування
Відкрийте касу й натисніть **⚙ Налаштування**: ключ ліцензії каси, логін і пароль або пін-код касира,
заокруглення готівки, платіжний термінал. Приклад файлу — `config.example.json`.

## Дані й журнали
| Система | Папка даних |
|---|---|
| Windows | `%LOCALAPPDATA%\Каса Checkbox` (або поруч із `Kasa.exe`, якщо там лежить `config.json`) |
| Mac | `~/Library/Application Support/Каса Checkbox` |

У папці даних: `config.json` (налаштування), `token.json` (токен касира), `checkbox.db` (товари, журнал,
передплати, акцизні марки, Z-звіти), `images/` (зображення плиток), `receipts/` і `reports/` (PNG чеків і звітів), `backup/` (копії перед
оновленням), `logs/`. Нічого з цього в репозиторій не потрапляє (див. `.gitignore`).

**Журнали** — `logs/kasa.log` (шлях видно в налаштуваннях; у Windows — також у меню значка в треї).
Формат — JSON-рядки (як у loguru): кожен запит до Checkbox з тілом запиту й відповіддю, обмін з терміналом.
Паролі, пін-коди, токени й ключі приховуються (`***`), телефони — частково (`38067*****67`).
`logs/update-helper.log` — кроки помічника оновлення у Windows, `logs/launcher.log` — запуск на Mac.

## Оновлення
Каса перевіряє [останній випуск](../../releases/latest) і показує банер «Доступна нова версія — Оновити»;
та сама кнопка є в **⚙ Налаштування** поруч із «Перевірити оновлення». Каса завантажує файл, звіряє
контрольну суму з `SHA256SUMS.txt`, робить резервну копію й перезапускається.

- Якщо API GitHub обмежив запити (60 на годину з однієї адреси), версію каса дізнається зі сторінки випусків,
  а файли бере за прямими посиланнями — ліміт API на них не діє
- Windows: нова версія зберігається як `Kasa.new.exe`; після виходу каси помічник (PowerShell, запущений через WMI)
  замінює `Kasa.exe` і запускає нову копію; залишки тимчасової папки `_MEI…` нова копія прибирає сама
- Версія — 3 або 4 числа (`1.4.6`, `1.4.6.16`); 4-значні каси розуміють починаючи з 1.4.6

Репозиторій для оновлень задається в `checkbox_app.py`: `GITHUB_REPO = "власник/назва"`.

## Випуск нової версії
1. Змініть `APP_VERSION` у `checkbox_app.py`, наприклад `"1.4.7"`.
2. Закомітьте й надішліть зміни.
3. Запустіть випуск: **Actions → «Випуск» → Run workflow** (тег `v1.4.7` створиться сам)
   або тегом: `git tag v1.4.7 && git push origin v1.4.7`.
4. GitHub Actions (`.github/workflows/release.yml`) збере `Kasa.exe`, `Kasa-mac.zip`, `kasa-py.zip`,
   `SHA256SUMS.txt` і опублікує випуск. Якщо версія в коді не збігається з тегом або такий випуск
   уже є — збирання зупиниться.

## Структура
| Файл | Що робить |
|---|---|
| `checkbox_web.py` | веб-інтерфейс і сервер каси (точка запуску) |
| `checkbox_app.py` | API Checkbox, локальна база SQLite, журнал, консольна версія |
| `goods_csv.py` | експорт/імпорт товарів у CSV, файл номенклатури Checkbox, поставка залишків |
| `kasa_update.py` | оновлення з випусків GitHub, перезапуск, прибирання після оновлення |
| `mac/` | збирання «Каса.app» для macOS |
| `win/Зібрати exe.bat` | ручне збирання `Kasa.exe` на Windows |
